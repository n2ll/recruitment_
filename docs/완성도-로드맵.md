# 옹보딩 완성도 로드맵 — 고완성도 제품 도약 단계

> 작성 2026-06-18 · 기준: 토큰 리스킨 완료 시점.
> 연계: `docs/ux-audit.md`(기능·UX 결함 목록) · `docs/design/DESIGN.md`(스타일 가이드) · `.cursor/rules/40-design-system.mdc`(디자인 시스템은 하한선).

## 0. 지금까지 (baseline — 이미 갖춰진 것)

- **토대 구축 완료**: 디자인 토큰(`app/globals.css`) + Tailwind v4 + shadcn 프리미티브 세트
  (`components/ui/`: button·card·badge·input·select·dialog·toast·confirm·prompt·table·states·command-palette·count-up).
- **신규 컴포넌트**(Dashboard·Pipeline·Recommend·AppShell·Wordmark)는 토큰 + framer-motion 적용.
- **전 레거시 뷰 색 리스킨 완료**(당근·배민·구인 에이전트·플레이그라운드): 비비드 신호등색 → 뮤트 팔레트.
  단, **색만** 토큰화했고 구조(inline `<style>` + 커스텀 클래스)는 그대로다.
- `components/ui/states.tsx`에 `ErrorState`/`EmptyState`/`Skeleton`/`LoadingState` 이미 존재
  (`ErrorState` 카피가 감사 A-1 권장값과 동일 — **연결만 하면 됨**).

## 1.5 레퍼런스 갭 (Huddle 프레임 대조)

> 출처: `Downloads/ref_huddle_frames/` 18프레임 (Huddle 랜딩 스크롤 캡처).

**전제**: 레퍼런스는 **마케팅 랜딩**, 우리 주력 화면은 **고밀도 운영 대시보드(ATS)**다. 표면 종류가 달라 1:1 이식은 부적절하다(운영자는 밀도·스캔성이 생명). 색 리스킨은 룰 40의 "하한선"만 올렸고, 레퍼런스의 "천장"(아래 7요소)은 미적용 — 이게 거리감의 정체이며 **부분적으로 당연하다.**

레퍼런스 디자인 언어 7요소 → 우리 적용처:

| Huddle 요소 | 관찰(프레임) | 우리 적용 표면 |
|---|---|---|
| 에디토리얼 타입 스케일 | 초대형·라이트 헤드라인 + 넉넉한 행간 (hero) | 대시보드 헤더 · `/apply` · 완료 · 빈/에러 상태 |
| 색=섹션 (풀블리드 블록) | 머스터드/세이지 듀얼 CTA, 라벤더 푸터, 로즈 티커 | 대시보드 랜딩 · 지원폼 섹션 · 확정/완료 |
| 큰 라운드 카드 (pastel fill) | r16~20·넉넉 패딩·내부 태그 pill·상태별 색(ONGOING/ACTIVE/SHIPPED) | 추천 카드 · 확정 슬롯 · 지원자 카드 |
| 마이크로 라벨 | `• ACTIVE` `‣ ONGOING` `SHIPPED ✦` 아이브로우 | 카드·섹션 헤더 (eyebrow 컴포넌트화) |
| 데이터-비주얼 카드 | "Your Wallet": 큰 숫자 + 미니 라인차트 + ▲% pill + 플로팅 알림 | 대시보드 KPI · 비용(usage_daily_cost) · 펀넬 |
| 라이브 티커/마퀴 | 회전 활동 메시지 밴드("Kyle just joined…") | 대시보드 상단 "방금 지원/확정" 실시간 띠 |
| 모션 | 스크롤 카드 라운딩 · 플로팅 알림 등장 · 마퀴 | Phase 3 전환/등장 |

**표면별 정책 (중요 — 무절제 이식 방지):**
- **저밀도 표면**(대시보드 랜딩 · `/apply` · 완료 · 빈/에러 · 로그인) = 레퍼런스 풀 표현 OK.
- **고밀도 표면**(지원자 목록 · 대화 · 칸반 · 인박스) = **절제.** 초대형 타입·풀블리드는 헤더/빈상태에만, 본문은 밀도·스캔성 유지.

## 2. 단계 (Phase)

각 Phase는 *목표 → 작업 → 인수기준(verify) → 연계 감사항목 → 리스크* 로 구성. 권장 착수 순서는 1→2→3→4.

---

### Phase 1 — 안전·신뢰 하한선 (즉효·저위험, 데모 직전 최우선)

**목표**: "데모 중 매니저가 오판하거나 실수로 실SMS를 날리지 않는다." 화면 큰 변화 없이 신뢰도 급상승.

**작업**
- `ErrorState`를 모든 로더에 연결(G3/A-1): `app/admin/page.tsx`(`fetchData`/`fetchBranches`/`openChat`)·`DanggeunView`·`AgentJobsView`·`PendingInboxView`·`PromptExamplesView`. 에러 state를 빈 state와 분리 + 재시도.
- native dialog → 공용 `confirm`/`prompt`/`toast` 치환(G2/C-15): 특히 `AgentJobsView` 재개 사유 `prompt`, 잔여 `alert`.
- Enter 무확인 실SMS 가드(G4/A-3): `AgentJobsView` 패널 Enter=줄바꿈·버튼=발송 분리(또는 첫 발송 확인).
- 중복클릭 가드(G4/A-5): `DanggeunView` 일시정지·단계변경·재개 버튼에 진행 중 `disabled` + "처리 중…".
- 지원자 목록 인라인 종료성 상태 confirm(A-2 잔여) — 당근 뷰 기존 패턴 이식.

**인수기준**: 로드 실패가 빈 상태로 안 보임 / 무확인 실발송 경로 0 / 종료성 상태 전환에 확인 / 비동기 버튼 중복클릭 불가.
**리스크**: 낮음 (로직 가드 추가, 레이아웃 무변).

---

### Phase 2 — 레거시 뷰 구조 이관 (CSS 부채 청산 + 프리미티브 채택)

**목표**: "색만 입힌 레거시"를 진짜 컴포넌트로. 반응형·접근성·빈/로딩 상태가 *공짜로* 따라온다.

**작업**
- inline `<style>` 뷰(`DanggeunView`·`AgentJobsView`·`PlaygroundView`)를 Tailwind + 프리미티브로 구조 이관. 색 리스킨(완료)을 발판 삼아 단계적으로.
- 동시 해소: 반응형(G5/C-11) · 빈/로딩/스켈레톤(C-18·D-19) · 키보드/aria/포커스(G5/B-10·D-20~22)는 프리미티브 채택으로 자연 해소.
- 거대 파일 분리(G6): `app/admin/page.tsx`의 대화 패널·지원자 목록·상세를 컴포넌트로 추출(`ChatPanel`/`ApplicantDetailView` 선례 활용).
- C-12(이탈 입력소실) 가드를 `Dialog` 이관 시 **명시**(dirty 시 오버레이 클릭 닫힘 비활성 — 기본값이라 안 막으면 악화).

**인수기준**: 미디어쿼리 0 → 분할/모바일 폭에서 단일 컬럼 / `page.tsx` LOC 하향 / 키보드만으로 주요 동선 가능 / 모달 dirty 시 실수 닫힘 없음.
**리스크**: 중간 (구조 변경 — 단위 분할 + 회귀 확인 필수).

---

### Phase 3 — 프리미엄 인터랙션·모션 + 레퍼런스 디자인 언어 ("ceiling")

**목표**: 룰 40의 "천장"을 올린다 — §1.5의 Huddle 7요소를 **저밀도 표면 위주로** 적용해 "완성도 높은 제품"으로 도약. (고밀도 표면은 표면별 정책대로 절제)

**작업 — 레퍼런스 디자인 언어 (§1.5 대응)**
- **에디토리얼 타입 스케일**: 디스플레이 헤드라인 토큰 추가(대형·라이트·tight tracking·넉넉한 행간). 대시보드 헤더·`/apply`·완료·빈/에러에 적용.
- **색=섹션 + 큰 라운드 카드**: 추천/확정 슬롯/지원자 카드를 상태별 pastel-fill 큰 라운드 카드(r16~20·내부 태그 pill)로. 듀얼 CTA·푸터 밴드식 풀블리드 블록을 랜딩/완료에.
- **마이크로 라벨 컴포넌트화**: `• ACTIVE` 식 eyebrow 프리미티브(`components/ui`).
- **데이터-비주얼 카드**: 대시보드 KPI/비용(`usage_daily_cost`)을 "Your Wallet"식(큰 숫자 + 미니 라인차트 + ▲% pill + 플로팅 알림 토스트)으로 고도화. 펀넬·추천 점수 링도 craft 상향.
- **라이브 티커/마퀴**: 대시보드 상단 "방금 지원·확정" 실시간 활동 밴드(Realtime 연동).

**작업 — 모션·성능**
- 모션 원칙 정립(`DESIGN.md` 확장): entrance / transition / optimistic 표준화, framer-motion 일관 적용. 플로팅 알림 등장·카드 라운딩·마퀴.
- 마이크로인터랙션: 단계 전이·토스트 등장·count-up 확장(이미 보유), (선택) 칸반 드래그.
- 성능: 대형 리스트 가상 스크롤(배민 149명·인박스), 대화 자동 스크롤 정합(C-13 잔여).
- 명령 팔레트(⌘K) 강화.

**인수기준**: 저밀도 표면이 레퍼런스 톤에 근접(디스플레이 타입·색섹션·데이터카드 존재) / 주요 전이 60fps / 대형 리스트 스크롤 끊김 없음 / 고밀도 표면은 밀도 유지(과적용 없음) / 데모 "wow" 포인트 정의·확인.
**리스크**: 중간 (과한 모션·무절제 색섹션은 오히려 슬롭 — `40-design-system` + §1.5 표면별 정책 준수).

---

### Phase 4 — 접근성·반응형·QA 마감

**목표**: 프로덕션 품질 하드닝 + 재발 방지.

**작업**
- 포커스 트랩·첫 입력 자동 포커스(D-22), 아이콘 버튼 aria-label 전수(D-21), 키보드 전 동선(D-20).
- 반응형 전수 점검(분할/태블릿/모바일).
- `verify` 체크리스트 상시화(PR 템플릿/룰): "로드 실패≠빈 상태" / "모달 dirty 시 오버레이 닫힘 비활성" / "무확인 실SMS 경로 없음" / "종료성 상태 전환 확인".

**인수기준**: 키보드 only 통과 / 스크린리더 라벨 확인 / verify 체크리스트 PR 필수화.
**리스크**: 낮음~중간.

## 3. 권장 착수 순서 & 근거

1. **Phase 1 먼저** — 데모 신뢰·안전 직결, 프리미티브가 이미 있어 빠름, 화면 회귀 거의 없음.
2. **Phase 2** — 구조 부채를 갚아야 3·4가 쉬워진다(반응형·접근성이 여기서 대부분 해소).
3. **Phase 3** — "wow" 폴리시. 2가 끝나야 안전하게 모션을 얹는다.
4. **Phase 4** — 마감·하드닝·재발 방지.

> Phase 1은 대부분 "있는 프리미티브를 연결"하는 작업이라 비용 대비 신뢰 상승이 가장 크다. 데모가 임박하면 Phase 1만 먼저 완주해도 체감 완성도가 오른다.
